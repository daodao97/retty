# 手机终端滚动排查

代码基线：Retty `1dbb42a`，已发布 MyGo fork `913e9acb7a9a`。
本次发现并修正画面同步的额外等待；尚不能断言它解释了用户报告的全部滑动变化。

## 画面同步间隔

`writeScreens` 原来在收到上一帧确认后，再等待完整的自适应间隔（至少 16ms）。
实际帧周期因此叠加了传输、接收端处理和完整等待时间。
现在从上一帧发送开始计时，只等待间隔剩余的部分；单帧在途、旧更新合并、确认顺序和队列上限保持原有约束。

隔离内存连接为两个方向各加入半个 RTT，每次消费画面后更新源画面，40 次更新中丢弃前 5 次预热。
这测量可响应交互的协议更新周期，不模拟无线丢包或实际触摸输入。

| 模拟 RTT | 修改前中位间隔 | 修改后中位间隔 |
| --- | ---: | ---: |
| 0ms | 17.6ms | 17.3ms |
| 12ms | 31.3ms | 16.5ms |
| 40ms | 64.6ms | 42.4ms |

修改后为三次运行中位数的中位数。测试验证每次收到最新内容，不对调度时间设置通过阈值。

```sh
RETTY_SCREEN_SYNC_MEASURE=1 GOWORK=off go test -tags mygo_noinspector \
  -ldflags '-X github.com/egoist/mygo.production=1' ./internal/rex \
  -run '^TestScreenSyncScrollCadence$' -count=3 -v
```

该修改在电脑端会话服务中生效。覆盖手机或桌面 GUI 不会替换已经运行的服务；排查期间保留了原服务及其任务。

## 真机 Metal 缓冲对照

iPhone 16（iPhone17,3），iOS 26.6.2，同一生产配置测试包，使用固定 SDK 的隔离副本。
通过临时环境开关选择 `maximumDrawableCount` 为 3 或 2；其余渲染路径相同。
本地终端预置 3000 行含颜色、中英文和 emoji 的内容，通过 `Context.AnimationFrame` 自驱动、每帧滚动 2 DIP。
依次测量普通/重排终端与静止/持续输出组合，每组 360 帧；跳过各组前 30 帧。
临时 `CAMetalDrawable` presented handler 记录实际显示时间；不是用 CPU 耗时的倒数冒充屏幕 FPS。

| 缓冲数 | 实际显示间隔中位数 | 稳态 P95 | 结果 |
| --- | ---: | ---: | --- |
| 3（当前） | 16.64ms | 16.65ms | 两次运行；第二次四种组合均稳定 |
| 2（旧值） | 33.28ms | 33.29ms | 后两组的有效显示回调；第四组因总时限截断 |

2 缓冲运行的构建帧间隔 P95 约 44ms，帧内耗时 P95 约 33ms（包含等待 GPU/显示的时间）。
3 缓冲第二次运行的构建帧间隔 P95 不超过 16.8ms，未发现超过 25ms 的稳态帧间隔。
`presentedTime == 0` 的回调未计入实际显示分布；这些回调不能证明画面已显示。
因此没有回退 MyGo 的三缓冲改动。此测试排除了网络，不测量手指到画面的延迟，也不覆盖用户真实会话的全部内容。

临时测试入口、SDK 改动和测量日志只保存在忽略的 `.mygo/mobile-scroll-audit/` 中，未进入正常应用代码。
测试后重新使用 `GOWORK=off` 构建、验证签名和原有 entitlements，覆盖安装并正常启动手机 App。

## 尚未确认的因素

普通终端历史按整行滚动，小于一行的移动先累计；慢滑和惯性尾段可能看起来一格一格移动。这段逻辑早于近期缓冲改动，不能据此认定出现了回归。
部分鼠标感知的全屏程序需要远端处理滚轮输入，受上述协议周期和网络往返影响；普通本地历史滚动不走这个等待路径。
Mac 无 GPU 基准的约 0.12ms 普通帧、0.86ms 重排输出帧，只用于定位 CPU 工作，不能换算为手机显示帧率。
